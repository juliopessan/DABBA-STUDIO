01 / The shift

Make the method
repeatable.

The method already existed and worked. Five specialists, each with their own scope, producing artifacts in the right order.

What was expensive was the driving — someone had to trigger each phase, carry context from one to the next, and stitch together at the end what ended up scattered across loose files. Delivery quality depended on who was driving.

DABBA moves that orchestration into the system. The chain itself is untouched: same phases, same order, same personas, same commands.

"The value wasn't locked in the agents.
It was locked in the person who knew how to drive them."

05 / The hard part

Built to survive
a small model.

A weak model doesn't fail loudly — it quietly writes a generic project instead. Most of the machinery in this pipeline exists to catch exactly that, deterministically, in code rather than by asking the model nicely.

Domain drift A phase handed too much context stops writing about your RFP and starts writing about a generic project. The source RFP is re-anchored into every phase, and the carried context is bounded, so a later phase can't inherit a drift it has no way to detect.
Persona echo The model returns its own instructions instead of the artifact. Detected on the response, and the command is retried before the run continues with an empty chapter.
False clean bills of health Asked to audit its own traceability, a model reports Gaps Identified: None regardless of the truth. So the check isn't asked for — it's computed from the stored artifacts and printed whether or not the model agrees.
Numbers in a proposal The optional sixth agent writes the commercial narrative and is forbidden from emitting a single figure. Team, hours and cost are computed from the stored staffing plan and your rate card, then inserted after the prose is written.

07 / Your key, your machine

Local-first,
bring your own key.

Three providers are supported. When more than one key is present, this is the order of preference — and if a free model errors, rate-limits or runs out of quota, the next one is tried automatically.

01Gemini Recommended for client work
02OpenRouter Free tier · auto fallback
03Anthropic Claude

Nothing leaves the machine

Except the model call itself. The run history, every artifact and every generated report stay in a local SQLite file and a local folder, at the OS-standard location:

~/Library/Application Support/DABBA/

No account, no server to sign into, no telemetry. Delete the folder and the history is gone.
